# Architecture

## Request path

```
Browser (React 19 / Vite)
  │  TanStack Query hooks generated by Orval
  ▼
customFetch  (lib/api-client-react/src/custom-fetch.ts)
  │  relative /api/... paths, optional base URL + bearer token for mobile
  ▼
Express 5 API  (artifacts/api-server)
  │  pino-http logging → Clerk proxy → cors → body parsers → clerkMiddleware
  │  requireAuth resolves the user ID server-side
  ▼
Drizzle ORM → PostgreSQL  (lib/db)
```

Every response the API returns is parsed through a generated Zod schema before
being sent, so the wire format cannot drift from the spec without failing loudly.

## Packages

### `lib/api-spec`
Holds `openapi.yaml`, the contract for every endpoint, plus the Orval config.
`pnpm --filter @workspace/api-spec run codegen` writes:

- `lib/api-client-react/src/generated/` — React Query hooks and TS types
- `lib/api-zod/src/generated/` — Zod schemas and types used by the server

Both generated trees are derived artifacts and are regenerated rather than
hand-edited.

### `lib/db`
Drizzle schema (`src/schema/mindflow.ts`) and the pooled `db` client. Tables are
prefixed `mindflow_` and are all per-user, keyed by the auth provider's user ID:

`users`, `tasks`, `habits`, `expenses`, `health_metrics`, `growth_metrics`,
`goals`, `activities`, `calendar_preparations`.

### `artifacts/api-server`
Express app. `src/routes/mindflow.ts` carries the product behavior: seeding,
dashboard aggregation, and the per-pillar CRUD. `src/middlewares/requireAuth.ts`
rejects unauthenticated calls with 401 and attaches `userId`.
`src/middlewares/clerkProxyMiddleware.ts` proxies the Clerk Frontend API through
the app's own domain in production — it buffers length-unknown responses so the
deployment edge never sees a chunked proxied response.

### `artifacts/mindflow`
The web app. `App.tsx` wires Clerk, the query client and the wouter routes;
`components/layout.tsx` is the authenticated shell; `pages/` holds one page per
pillar. Theming lives in `src/index.css` as CSS custom properties with a light
and dark palette.

## Derived values

- **Flow score** = 70% share of habits completed today + 30% mean goal progress,
  rounded to an integer.
- **Next action** is the earliest scheduled incomplete habit; when everything is
  done, it becomes a rest prompt rather than an empty state.
- **Budget** sums the last seven days of expenses against the user's weekly limit.
- **Growth percent** compares the current audience against the previously
  recorded check-in, not against a rolling daily count.
